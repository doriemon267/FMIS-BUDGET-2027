DRAFT SAVE CACHE BUG - COMPLETE FIX DOCUMENTATION
================================================================================

PROBLEM SUMMARY
===============
After saving draft edits ("SAVE DRAFT" button), changes were stored in DB.
But upon page refresh (F5), the UI showed OLD amounts instead of saved edits.

This happened specifically for APPROVER users and other non-standard roles.

Example:
- User edits amounts in tables
- Clicks "SAVE DRAFT" → Database updated ✅
- Presses F5 to refresh → Old amounts appear again ❌


ROOT CAUSES - THREE ISSUES DISCOVERED
======================================

ISSUE #1: Missing editedBy Field in Database Documents
-------------------------------------------------------
PROBLEM:
- Existing BudgetOfficerEdit documents DON'T have the "editedBy" field
- Fetch query tries to filter by 'editedBy.userId' 
- Documents without this field are NOT FOUND

WHY IT HAPPENED:
- The editedBy field was added to schema AFTER some documents existed
- Old documents were never migrated
- New documents created after schema change DO have the field

EVIDENCE:
The database document you showed has NO editedBy field at all!


ISSUE #2: Incomplete Update When Modifying Existing Drafts
-----------------------------------------------------------
PROBLEM:
When user updated an existing draft, code only updated the ROLE:

  OLD CODE (line 954):
  budgetOfficerEdit.editedBy.role = editDocRole;

This assumes:
1. editedBy field already exists (it might not!)
2. Only role needs updating (other fields don't change)

WHY IT'S WRONG:
- If field doesn't exist, code fails silently or crashes
- If multiple users edit same draft, userId/userName become stale
- Fetch query won't find document because userId doesn't match


ISSUE #3: Query Finding Wrong User's Edit
-------------------------------------------
PROBLEM:
For non-standard roles (APPROVER, REVIEWER, etc.), fetch had NO userId filter:

  OLD CODE (lines 686-689):
  fetchQuery = {
    proposalId: proposal._id,
    status: { $in: ['Draft', 'Submitted'] }
    // ❌ NO userId filter!
  };

THE CONSEQUENCE:
If User A (APPROVER) and User B (APPROVER) edit same proposal:
- User A saves edit at 3:00 PM
- User B saves edit at 3:05 PM
- User B refreshes → findOne().sort({updatedAt: -1}) returns User A's NEWER edit
- User B sees USER A's DATA instead of their own saved edits!

This is a DATA LEAK!


================================================================================
THE FIX - THREE PARTS
================================================================================

PART 1: Update Existing Draft Save Operation
=============================================
File: SERVER/controllers/budgetOfficerEditController.js (lines 953-959)

BEFORE:
  budgetOfficerEdit.editedBy.role = editDocRole;

AFTER:
  budgetOfficerEdit.editedBy = {
    userId,
    userName,
    email: userEmail,
    role: editDocRole
  };

WHY THIS WORKS:
✅ Replaces entire object (no reliance on pre-existing fields)
✅ Updates ALL fields consistently
✅ Ensures save and fetch are in sync
✅ Works even if field was missing in legacy documents


PART 2: Add UserId Filter to Fetch Query
=========================================
File: SERVER/controllers/budgetOfficerEditController.js (lines 685-690)

BEFORE:
  fetchQuery = {
    proposalId: proposal._id,
    status: { $in: ['Draft', 'Submitted'] }
  };

AFTER:
  fetchQuery = {
    proposalId: proposal._id,
    status: { $in: ['Draft', 'Submitted'] },
    'editedBy.userId': userId  // ← CRITICAL FIX
  };

WHY THIS WORKS:
✅ Ensures users ONLY see their own edits
✅ Prevents another user's newer edit from overwriting your view
✅ Multiple APPROVER users can edit same proposal safely
✅ Each user sees their OWN saved drafts on F5 refresh


PART 3: Add Fallback for Legacy Documents
==========================================
File: SERVER/controllers/budgetOfficerEditController.js (lines 694-711)

Added fallback to handle documents without editedBy.userId field:

  if (!existingEdit) {
    const legacyEdit = await BudgetOfficerEdit.findOne({
      proposalId: proposal._id,
      status: { $in: ['Draft', 'Submitted'] },
      'editedBy.userId': { $exists: false }
    }).sort({ updatedAt: -1 });
    
    if (legacyEdit) {
      existingEdit = legacyEdit;
    }
  }

WHY THIS WORKS:
✅ Handles legacy documents without editedBy field
✅ Acts as safety net during migration
✅ Logs warnings so you know legacy docs exist
✅ Prevents accidental data loss
